# Worked case: orders released but not received, Nicola, 7 September 2026

Everything in this file is observation from screenshots and one log export
supplied by Dan on 7 and 8 September 2026, plus the manual sentences that
explain them. Support case: 500Tb00001NaIALIA3, "unable to send orders to the
order manager". Status at the time of writing: finding stated, fix not yet
applied, two confirmations outstanding.

## Finding

The Data Store cluster is configured with three nodes and one is running.
Front Office Configuration 16.4, page 161: with two nodes stopped, the
Workflow service can still read, but "no new data (any action or event that
results in the update of existing data or creation of new data such as the
arrival of new orders in the new Order Manager architecture) is written in the
Data Store cluster." Released orders therefore cannot be written, which is what
the Order Outbox reports as not received while every service shows a green
count of 1. The green cell is "Service is successfully started" in the log; the
quorum failure sits four seconds later.

## What the finding does not cover

- Why nodes 07 and 08 are down. The automation model Count for service 329
  and the two node logs decide between "stopped by the model" and "failed".
  A Count of one is the model asking for exactly this state.
- Whether the Data Store instance seen on NICOLAPROD08 in the morning pivot and
  the one on nicolaprod09 in the afternoon log are the same node moved, or two
  starts. The Start rows of both logs answer that.
- The assembly load exceptions. NOT VERIFIED either way.
- The lighter green External Integration cell. Its own log answers that.
- The four hour difference between the Date column and the timestamps embedded
  in the connection close lines. Time zone of the embedded value not stated.

## The change this points at, and what it needs first

Service 329 with a Count of three in NICOLAPFW, one instance per dedicated
machine through service tags and `-maxrunningservices=1` on those agents
(16.4.6, page 165), in a group that starts before Workflow, which starts before
the Order service (16.4 note). Before applying: the current Content tab of
NICOLAPFW for services 329, 328 and 64; the Workflow Server Parameters tab
Hostname and Directory path rows; confirmation that directories on 07 and 08
hold valid EventStore files (16.4.1); and the model change performed as
Maintenance, Edit Model, Apply, Enable, Production (Service Administration
6.1.3). Proof of the fix is the last section of `02-data-store-cluster.md`.

## Side findings recorded on the way

- The STP order status queue fields on Extra Information are not documented in
  the Front Office Configuration manual (September 2025 or March 2026). Message
  queue blank with status On Hold matches the FO_OM_MQ rows having been removed
  from Order Defaults (Louis, 21 August 2026, 0 of 190 orders stamped).
- The four Nicola auxiliary jobs trigger on direct orders at Entry dir. A
  Portfolio order class at Released does not enter that chain, so no aux job
  and no message queue entry is expected for it.
- Order deleted after release is logged with Event type Change request.
